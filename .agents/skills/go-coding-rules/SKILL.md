# Go 编码规则

以下规则为强制约束，逐条执行。

## 语言版本与工具链

1. 目标运行环境固定为 `go.mod` 声明的 Go 版本；只写该版本支持的语法，禁止为更低版本保留兼容分支。

2. 新增依赖前先确认标准库或现有依赖能满足需求；确需引入时用 `go get` 写入 `go.mod`，禁止手工编辑依赖版本号。

3. 构建产物只写入 `bin/` 或 `tmp/` 目录；禁止把可执行文件与测试产物提交到版本库。

## 语法克制

4. 用标准库与语言内置能力完成任务；同等效果下选阅读者无需查文档就能看懂的那一种。

5. 禁止用 `reflect` 动态建类型、动态调用方法或注入属性；用显式结构体、接口与普通函数替代。

6. 禁止使用 `unsafe`；需要直接操作内存时先改用标准库或重新设计数据结构，确需绕过类型系统时先向用户说明并取得同意。

7. 禁止在 `init()` 中执行业务逻辑、读取配置或发起网络请求；初始化交给 `main()` 或构造函数。

8. 单个表达式的链式调用与嵌套不超过三层；超出时拆成带名字的中间变量。

## 代码组织

9. 每个包只承担一项内聚职责；包名用小写单词，禁止 `utils`、`common`、`helpers`、`models` 这类无边界包名，改用职责明确的包名。

10. 需要可变状态、配置或协作者时用结构体方法；行为无状态且只作用于入参时用普通函数。

11. 依赖通过构造函数显式传入；禁止用包级变量保存数据库连接、配置单例或日志实例。

12. 接口定义在消费方所在包，且只声明调用方实际使用的方法；禁止在实现方预建接口或为将来预留方法。

    > 示例：
    >
    > ```go
    > type NotebookReader interface {                       // 用：消费方按需定义
    >     GetByID(ctx context.Context, id string) (*Notebook, error)
    > }
    >
    > type NotebookRepository interface { /* 全部方法 */ }   // 禁止：实现方预建大接口
    > ```

13. 接受接口、返回结构体；禁止返回接口或接收具体实现指针。

14. 优先用组合；继承关系只用结构体嵌入表达，且嵌入类型必须与宿主是明确的“属于”关系。

15. 禁止为尚不存在的变体预建工厂、注册表、策略或泛型基类；等第二种实现真正出现时再抽象。

16. 每个类型与每个函数只能有一个变更原因。

## 命名

17. 包名用小写单词，禁止下划线、复数与 `util`、`common` 前缀。

18. 导出标识符用 `MixedCaps`，未导出标识符首字母小写，首字母缩写整体大写或整体小写；禁止下划线命名与 `Url`、`Id`、`Http` 写法，测试函数与生成代码除外。

19. 禁止名称重复包名、类型名或命名空间已表达的信息。

    > 示例：`notebook.NotebookService` 禁止；`notebook.Service` 用。

20. 错误值用 `ErrXxx`，自定义错误类型用 `XxxError`；禁止 `Failure`、`Exception` 后缀。

21. 接口用能力名或 `-er` 后缀；禁止 `I` 前缀、`Base` 前缀与 `Impl` 后缀。

22. 函数名以动词开头，返回布尔值时用 `Is`、`Has`、`Can`、`Should` 前缀；名称控制在 1-4 个词。

23. 接收者名用类型名首字母的小写形式，同一类型在全项目保持一致；禁止 `self` 与 `this`。

24. 同一概念全项目只允许使用一个名称。

## 类型与接口

25. 已知结构的数据用结构体承载；禁止用 `map[string]any` 或 `any` 跨包边界传递。

    > 示例：
    >
    > ```go
    > func Handle(payload map[string]any) error        // 禁止
    > func Handle(payload CreateNotebookInput) error   // 用
    > ```

26. 可选语义用指针或带 `Valid` 字段的结构体表达；禁止用零值同时表示“缺失”与“未设置”。

27. 固定取值集合用自定义类型加常量；禁止用裸字符串或整数散落在代码中。

28. 相关常量用 `const` 块与 `iota`；常量名用 `MixedCaps` 并带单位后缀。

29. 时间用 `time.Time` 与 `time.Duration`；禁止用 `int64` 秒数或字符串跨层传递时间。

30. `context.Context` 必须作为函数的第一个参数并命名为 `ctx`；禁止把 `ctx` 存进结构体。

31. 同一函数的不同分支必须返回同一类结构；禁止一个分支返回结构体、另一个分支返回 `map`。

## 错误处理

32. 可恢复错误用 `error` 返回；禁止用 `panic` 处理业务失败。

33. 包装错误用 `fmt.Errorf("...: %w", err)`；禁止用 `%v` 丢掉错误链。

    > 示例：
    >
    > ```go
    > return fmt.Errorf("create notebook: %w", err)   // 用
    > return fmt.Errorf("create notebook: %v", err)   // 禁止
    > ```

34. 判断错误用 `errors.Is` 与 `errors.As`；禁止比较错误字符串。

35. 哨兵错误定义在所属包并命名 `ErrXxx`；调用方用 `errors.Is` 判定，禁止在多层重复定义同一错误。

36. 捕获错误后只允许记录日志、释放资源、回滚或返回包装后的错误；禁止吞掉错误返回零值。

37. 清理资源用 `defer`；`defer` 必须在错误分支与正常分支都能执行。

## 并发

38. 跨层传递取消与超时用 `context.Context`；禁止在 goroutine 中丢弃调用方的 `ctx`。

39. 启动的每个 goroutine 必须有明确的退出路径与归属方；禁止 fire-and-forget。

40. 并发数量必须有上限；用带缓冲的 channel、信号量或 `errgroup.SetLimit` 控制，禁止无界启动 goroutine。

41. 共享可变状态用 `sync.Mutex` 或 `sync.RWMutex` 保护；锁的持有范围覆盖读写字段的最短区间。

42. channel 只允许用于传递数据与所有权；禁止用 channel 模拟共享状态或替代简单函数调用。

## 外部依赖隔离

43. 第三方 SDK、数据库驱动、消息队列与远端 API 必须封装在 adapter 或 client 包；业务层禁止直接依赖供应商类型。

44. 封装层只暴露原子操作；禁止把业务流程编排写进封装层。

45. 第三方响应与错误必须在封装边界转换为项目自己的结构体与错误；禁止供应商类型扩散到调用方。

46. 已有封装层时直接复用，局部且只使用一次的调用保持直接调用；禁止另建平行封装。

## 日志

47. 日志统一用 `log/slog`；禁止使用 `log.Printf`、`fmt.Println` 或第三方日志库。

48. 记录结构化字段用键值对参数；禁止用字符串拼接整条日志。

    > 示例：
    >
    > ```go
    > log.InfoContext(ctx, "notebook created", "notebook_id", id)   // 用
    > log.InfoContext(ctx, fmt.Sprintf("notebook %s created", id))  // 禁止
    > ```

49. 需要请求上下文时用 `InfoContext`、`WarnContext`、`ErrorContext`；禁止丢弃 `ctx`。

50. 日志禁止写入密钥、令牌、完整连接串与敏感请求体；同一异常调用链只在一处记录错误日志。

## 注释与文档

51. 导出的类型、函数、方法、常量与变量必须有以名称开头的文档注释。

52. 注释说明为什么这样做与使用约束；禁止复述代码在做什么。

53. 注释语言遵循 `hiduck/general-rule/chinese-output.md`：新增文件用简体中文，修改既有文件跟随该文件已有语言。

54. 内部函数只在契约、副作用或算法不直观时写注释；禁止为每个函数机械补注释。

## 入口与装配

55. 可执行程序入口只放在 `cmd/<name>/main.go`；`main()` 只调用 `run() error`，失败时记录后 `os.Exit(1)`。

56. `run()` 是组合根：读取配置、构造依赖、启动服务；禁止在其中写业务规则。

57. 依赖在组合根显式构造并逐层传入；禁止用 `init()` 或包级变量完成装配。

58. 进程退出前必须调用资源释放与优雅关闭；禁止直接 `os.Exit` 跳过 `defer`。

## 变更纪律

59. 编辑前先读相关代码、项目约定与邻近测试，优先复用或扩展现有实现，禁止创建平行抽象。

60. 只实现本次任务所需的行为；禁止顺带做无关重构。

61. 完成后运行 `go test ./...`、`go vet ./...` 与 `golangci-lint run`；无法运行时明确说明原因。
